# 97% of llms.txt Files Go Unread. Your Docs Are the Agent Interface Now

**A 2017 documentation framework hit the Hacker News front page with 393 points this weekend — not because writers rediscovered it, but because developers found they can type “do diataxis” at a model and get usable docs out. Meanwhile the file we were all told to ship for machines is being ignored on 97% of the sites that ship it. The lesson is uncomfortable and immediately actionable: machines read the thing you actually wrote, not the thing you wrote for machines.**

## Key Insights

Three signals landed within a few days of each other, and they only make sense together.

**Diátaxis** — Daniele Procida’s four-quadrant documentation framework (tutorials, how-to guides, reference, explanation), published years before the agent era — reached the HN front page on August 1 with **393 points and 49 comments**. The comment thread is the interesting part, not the link. The top-voted reaction is a confession: *“I never saw the point in Diataxis, but honestly while vibe coding it’s pretty convenient to tell an LLM ‘do diataxis’ and get decent first pass documentation out of it.”* Others describe crawling the Diátaxis site to build a personal skill file, or handing an agent a directory of screenshots and having it produce a structured guide. A taxonomy that struggled to justify itself to humans for a decade got instant adoption the moment it became **a compressible instruction for a model**.

Against that, **Ahrefs analyzed 137,000 sites and found 97% of llms.txt files are never read** by the crawlers they were built for. The industry spent a year shipping a dedicated machine-readable manifest, and the machines mostly did not pick it up. They crawled the real pages instead.

Put those together and the conclusion is blunt. **The interface machines use is your actual documentation, structured. Not a side-channel file, not a metadata blob, not a schema you bolted on.** The winning move is not “add a file for AI.” It is “make your real content structurally unambiguous,” because that same structure serves both an agent parsing your API and a human trying to install it.

The third signal supplies the counterweight. **Bor v0.8.0** shipped on August 2 — open-source policy management for Linux desktop fleets. Its architecture is a rebuke to how we currently govern agents: the agent writes a managed config file, validates it with the tool’s own checker (`firewall-cmd --check-config`), reloads the service, and runs a **tamper watcher that detects external edits and immediately restores the managed state**. Removing the last bound policy restores the original file. Compare that to the enterprise agent benchmark data circulating this week: the best of thirty model configurations passes **36.2%** of tasks when governance is a written handbook in context. **Written rules get followed a third of the time. Enforced rules get followed every time.** Both belong in the same product, and almost nobody is building the second half.

**Numbers that should change a decision:**

- **97% of llms.txt files never read** across 137K sites (Ahrefs). If you shipped one, it is not doing what you think, and effort should move to document structure
- **393 points** for a docs taxonomy on HN in 2026. Documentation stopped being a chore and became a machine interface with measurable output quality
- **36.2%** best strict pass rate when policy lives in a prompt vs. deterministic enforcement, which does not have a pass rate because it does not negotiate
- **~10% Linux desktop share in North America** per the figures circulating this week — directional, but the r/linux thread pulled 168 points and 77 comments because the number is no longer a rounding error. A new fleet surface with almost no SMB tooling around it

## Market Trends

### Documentation became a compile target, and structure is the compiler

For ten years, docs frameworks lost the argument for the same reason style guides lose it: humans skim, humans tolerate mess, and the payoff for rigor is diffuse. One HN commenter captured the old dynamic exactly — Diátaxis was “the kind of thing that makes docs people justify their jobs rather than coming from a founder or user centric pov.”

That objection died the moment a model could execute the framework. Structure is now **cheap to apply and expensive to lack**. Cheap, because “do diataxis” is three words and a competent model produces a defensible first pass. Expensive, because the retrieval layer, the coding agent, and the AI search engine all parse your content, and ambiguity in your prose becomes wrong answers about your product with your name attached.

Notice which artifact won. Not `llms.txt` — a file explicitly designed as the machine channel, ignored on 97% of the sites that publish it. The framework that won was one that **improves the human document itself**. This is the practical rule for the next year: any “AI-readable” investment that lives in a parallel channel — a side file, a hidden div, a metadata pass — is speculative and depends on crawler adoption you do not control. Any investment that makes your primary content clearer is unconditional. It works for humans, it works for every current crawler, and it survives the next protocol churn.

The second-order effect matters more for anyone selling to developers. Your documentation is now a **compatibility layer with the tools your customers use to build**. If a developer’s agent can read your reference section and produce working code on the first attempt, you have a structural advantage over the competitor whose docs are a narrative blog post — and that advantage compounds silently, because the developer will never file a bug that says “your docs confused my agent.” They will just use the other thing.

### Enforce, don’t describe: the governance gap has a working reference implementation

The dominant pattern for controlling agents is a document in context — system prompt, policy file, skills markdown, `AGENTS.md`. Every product ships some version of it. The benchmark evidence says it holds about a third of the time under strict grading, with a consistent failure signature: a plausible in-context request overrides the standing rule, the agent runs the required check and then acts against the result, and rule fidelity decays over long horizons.

Bor’s release notes describe the alternative, and it is worth reading as an architecture spec rather than as Linux news:

- **Write the managed artifact, don’t request compliance.** The agent writes `policies.json` / `bor_managed.json` / zone XML into the location the target software actually reads
- **Validate with the target’s own validator** before applying. `firewall-cmd --check-config` is the arbiter, not the model’s confidence
- **Watch for tampering and restore.** Drift is detected and corrected without a human in the loop
- **Clean reversal.** Removing the last bound policy restores the original file — the system knows how to unwind itself
- **Per-action permissions**, not one blanket admin scope

Every one of those is a missing feature in the average agent product. The industry is building the *reasoning* layer and calling the *enforcement* layer a prompt. The gap between 36.2% and deterministic is where a real product sits: let the agent decide, then run the decision through a validator that cannot be argued with, and log the whole exchange as evidence.

If you sell into anything with a consequence — money movement, medical coding, infrastructure changes, contract terms — this is your specification. **Not a smarter agent. A dumber, unbribable checkpoint sitting downstream of it.**

### Solo scope expanded again, and small is beating big for distribution

Three data points from the same week that are easy to dismiss individually:

- A developer shipped a **new browser engine that passed Acid 3 after two years of solo work** (141 points). Browser engines were a hundred-engineer proposition a decade ago
- A solo builder rebuilt an arcade game in HTML5 at **under 100KB, no ads, no logins, no loading**, explicitly crediting a single model as their pair (42 points). New track daily, one URL, forever
- **Show HN: Elevators** — a whimsical single-purpose page — took **1,604 points and 395 comments**, out-performing every funding announcement and model release on the site that week

The pattern is not “AI makes you fast.” That is priced in. The pattern is that **attention is now flowing to the smallest, most immediate artifacts** at exactly the moment production capacity went infinite. When everyone can generate a polished landing page and a feature grid, the thing that stops the scroll is a page that loads in 300ms, does one thing, asks for nothing, and does not want your email.

For a solopreneur this is a distribution strategy, not an aesthetic. The sub-100KB no-login toy is the cheapest top-of-funnel asset available in 2026, and it is one of the few that AI abundance makes *more* valuable rather than less — because its scarcity is not in the code, it is in the restraint.

## Build Directions

### 1. Agent-readability audits and Diátaxis restructuring (fastest path to revenue)

**What to build:** A productized service and eventual tool that restructures a company’s docs into the four Diátaxis quadrants and proves the delta. The proof is the product: pick 10 realistic tasks against the customer’s API, run them through a coding agent using only the public docs, record first-attempt success. Restructure. Re-run. Ship a before/after number.

**Why now:** The framework just went mainstream on the strength of being model-executable, 97% of llms.txt files are dead weight so budgets are looking for something that works, and no incumbent owns “your docs are failing your customers’ agents” as a category.

**Stack:** `Claude Code` or equivalent for the bulk restructuring pass (this is exactly the “do diataxis” workload). A headless agent harness for the benchmark runs — script 10 tasks, log first-attempt pass/fail, no framework required. `Docusaurus` / `Mintlify` / whatever the client already uses for output. A diff report as the deliverable.

**Cost & timeline:** Near-zero capex; inference for a full docs pass runs into the low tens of dollars. **First engagement deliverable in 5–10 days.** Price at $2,000–$8,000 per engagement depending on surface size, then productize the benchmark harness into a subscription once you have run it fifteen times and know what breaks.

**Wedge:** Developer-tool companies with 20–200 person headcount. They have docs, they have no docs team, and their customers are the exact population using agents.

### 2. Deterministic enforcement layer for agents (highest conviction, biggest gap)

**What to build:** The validator-and-restore layer described above, sold as the thing that makes an agent deployable. The agent proposes; your layer independently verifies against a real checker; non-conforming actions are blocked and logged; state drift is detected and reverted; every decision produces an audit record.

**Why now:** A written-policy ceiling around 36.2% is not a model problem you can wait out — it is a structural property of putting rules in the same channel as instructions. Enforcement lives outside that channel by construction. And Bor just published a clean reference architecture for the pattern in a different domain, which is worth studying line by line.

**Stack:** Whatever validator the domain already trusts — a schema, a linter, a rules engine, the vendor’s own `--check` flag, a database constraint. `OPA / Rego` if you need general policy expression. Append-only log in `Postgres` or `SQLite` with a hash chain for tamper evidence. The model layer is interchangeable and should be treated that way.

**Cost & timeline:** **8–12 weeks to a defensible first vertical.** The engineering is not exotic; the hard part is picking a domain where the correct answer is machine-checkable. Start where a validator already exists and you are half done.

**Vertical picks:** Cloud/IaC change review, invoice and expense policy, medical billing code validation, marketplace listing compliance, contract clause checks against a standing playbook.

### 3. Linux desktop fleet tooling for the SMB gap

**What to build:** The management layer around the Linux desktop share that just stopped being negligible. Bor covers policy for a technical operator; what does not exist is the boring commercial wrapper — onboarding, compliance reporting for auditors, drift dashboards, and a per-seat SaaS that a 40-person shop can actually buy.

**Why now:** North American Linux desktop share crossed into double digits in the figures circulating this week. Every percentage point of that is a machine with no MDM, no baseline, and an owner who will fail their first security questionnaire. The tooling that exists is either enterprise-priced or hobbyist-grade.

**Stack:** Fork or build atop `Bor` (Go agent + gRPC/mTLS, open source — **verify the license before you commercialize**). `PatternFly` or your own UI. Compliance report generation is a straightforward templating job against the policy state you already store.

**Cost & timeline:** **10–14 weeks**, and most of it is not code — it is the compliance-report templates and the onboarding path. Price per seat per month; the buyer is an ops lead who is currently doing this with Ansible and hope.

### 4. Sub-100KB, no-login utilities as a distribution engine

**What to build:** Not a business — a funnel. One page, one function, instant load, zero accounts, zero permissions. Then a quiet link to the paid thing you actually sell in the same domain.

**Why now:** The evidence is right there in the week’s leaderboard: a playful single-purpose page pulled 1,604 points while substantive product launches pulled two figures. A solo dev’s sub-100KB game earned a front-page slot on load time and restraint alone. And on the permissions axis, a Show HN Android file viewer positioned entirely on **asking for zero permissions** — that is now a feature you can lead with.

**Stack:** Vanilla JS or a tiny framework, `Cloudflare Pages` or `GitHub Pages` for hosting at effectively zero cost, a model for the build itself. Deliberately no analytics SDK, no auth, no cookie banner — the absence *is* the pitch.

**Cost & timeline:** **A weekend.** Hosting cost rounds to zero. Expect most attempts to land nothing; the distribution is lottery-shaped, but the ticket is nearly free and the residual asset is permanent.

### 5. Local-first vertical apps on real sync infrastructure

**What to build:** A vertical application for professionals who work in bad-connectivity environments and cannot legally or practically stream data to a server — field inspection, clinical intake, site survey, maritime and remote logistics.

**Why now:** The offline-first sync layer is finally becoming a component rather than a project. `Syncular` surfaced this week with TypeScript and Rust cores for offline-first SQL sync, joining an increasingly credible field. Meanwhile local inference keeps getting cheaper. Local-first plus local model equals a product whose data never leaves the device, which is a compliance answer rather than a compliance risk.

**Stack:** `Syncular` or comparable for sync, `SQLite` local store, a small local model for on-device extraction and summarization, thin cloud tier only for what genuinely must be shared.

**Cost & timeline:** **10–14 weeks.** Conflict resolution is where the schedule goes; design the data model to minimize genuine conflicts before you write sync code, not after.

## Risk Factors

- **Docs restructuring is only defensible if you measure it.** Without a before/after agent-success number, you are selling a rewrite and competing on hourly rate. The benchmark harness is the moat; build it first, do the writing second.
- **`llms.txt` is the cautionary tale for every “AI-readable” standard.** 97% unread. Do not build a business on a convention whose adoption is controlled by four crawler teams who have shown they will ignore it. Build on the content itself.
- **The enforcement layer is a race against platform vendors.** Model providers will eventually ship guardrails and audit primitives. Your defense is domain-specific validators and the evidence format an auditor in that industry will accept — neither of which a horizontal platform will build.
- **Linux desktop numbers are directional, not bankable.** Share figures from analytics panels move with methodology and are contested every time they are posted. Validate with actual buyer conversations before committing a quarter to it.
- **The tiny-artifact funnel is lottery-shaped.** For every front-page toy there are a thousand that reach nobody. Budget it as marketing spend at near-zero cost, never as a product line, and never let it consume a week.

## Action Recommendations

**If you are starting out:**

- ✅ Run the audit on your own docs before you sell it. Ten realistic tasks, a coding agent, public docs only, log first-attempt success. The number will be worse than you expect, and it is your first case study.
- ✅ Delete or de-prioritize your `llms.txt` work. Spend that hour splitting one confused page into a how-to and a reference section instead.
- ✅ Ship the weekend micro-utility. Sub-100KB, one function, no login, no analytics. Treat it as a distribution experiment with a fixed 48-hour budget.
- ✅ Pick one domain where a validator already exists and prototype the enforce-don’t-describe loop against it. If you cannot name the validator in one sentence, pick a different domain.

**If you are running something established:**

- ✅ Add first-attempt agent success on your own docs to your metrics. It is a leading indicator of developer churn that no support ticket will ever surface.
- ✅ Audit where your product governs behavior with a document rather than a check. Every one of those is a ~36% reliability surface wearing a confident interface.
- ✅ Instrument reversal, not just action. Bor’s cleanest idea is that removing a policy restores the prior state. Most agent products cannot cleanly undo what they did, which is the real reason enterprises will not grant them scope.
- ✅ If you sell developer tooling, restructure the reference section first. It is the section agents hit hardest and the one most often written as prose.

## What It Means

The through-line is that **the machine-readable era did not arrive as a new file format. It arrived as a quality standard on the things we already write.** The dedicated AI channel — the manifest, the side file — was ignored. The old, unglamorous discipline of structuring a document properly got adopted overnight because a model could execute it.

The same logic governs the other half of the week. We tried to make agents behave by writing them a document, and we got roughly a third compliance. The systems that actually hold — the ones that write the managed file, validate with the real checker, and restore on drift — do not describe the rule at all. They make the wrong state impossible to persist.

**Write clearly for machines by writing clearly. Govern machines by enforcing, not asking.** Both halves are unglamorous, both are underbuilt, and both are available to a single person with a laptop this week.
