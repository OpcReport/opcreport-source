# A Solo Terminal Runtime Hit 25k Stars and 500 Plugins in a Month — Then Got Into YC

**August 7, 2026 · Issue #11**

---

## Key Insights

Buried in the post announcing that Herdr is joining Y Combinator is the single most useful tactical sentence I have read for indie developers this half-year. Can Celik, the only person behind the project, writes:

> *“You know how every company releases their own agent these days? No, don’t do that. Let my agent integrate with your product, don’t offer me another agent.”*

He did not build a smarter agent. He built the **runtime** agents run inside. The result: **25,051 GitHub stars, 340,000 downloads, and 500+ third-party plugins one month after the marketplace opened.** A Raycast extension, a Stream Deck integration with physical buttons, an iOS app that drives an entire session from a phone — **he built none of them.**

The agent layer is saturated and undifferentiated. The layer *underneath* it — the runtime — and the layer *on top of it* — plugins — have distribution costs approaching zero. That is the whole thesis for this issue. **Do not build agent number 4001. Build the floor it stands on, or the pipe that plugs into it.**

### Numbers that actually change decisions

- **25,051 stars / 340k downloads / 500+ plugins in one month.** Solo project, Apache-2.0, now YC F26. The plugin marketplace is currently the most underrated distribution channel available to indie developers.
- **$0.05 → $1.80 per task. A 36x price spread buys you 11 points of intelligence.** Same Intelligence Index, different tiers: GPT 5.6 Luna max $0.05 (52), Grok 4.5 high $0.36 (56), GPT 5.6 Sol xhigh $0.81 (59), Qwen3.8 Max $1.13 (58), Opus 5 xhigh $1.80 (63). **If everything you run defaults to the top tier, you are bleeding margin for no reason.**
- **Cache hit price $0.25/M tokens vs $2.00 input — 88% cheaper.** For any agent product that re-feeds the same long context, prompt caching is not an optimization. It is the difference between a viable and non-viable unit economic.
- **Prime Agent is open source, one curl to install.** Sub-agents are function calls in a live IPython REPL (`await rlm("subtask")`). Idle sub-agents unload from memory after 30 minutes and reload from disk on demand. The harness architecture is being rewritten in public, and you can read all of it.

## Market Trends

### 1. Value is moving down the stack, from the agent to the thing the agent runs on

The Herdr case rewards a close read. Four months ago the author was job hunting and grinding whiteboard interviews. His framing of the problem: **“I am the bottleneck.”**

What he built instead of another assistant was a set of **terminal primitives.** A pane belongs to an agent. A pane belongs to a tab. Tabs belong to a project. Agents now run for hours, sometimes days, so all of it must persist. And once you have a runtime, **where the agent runs stops mattering** — laptop, VPS, sandbox, all the same.

The distribution insight is in the client choice. The bundled TUI stays first-class forever for one blunt reason: **it ships inside the binary.** Install Herdr on a VPS, ssh in, and the UI is already there. Or run `herdr --remote user@host` and it installs itself. One command and an agent is running.

**Then the ecosystem did the rest of the work.** Raycast extension, Stream Deck buttons, an iOS app running full sessions from a phone — all community-built. 500+ plugins in the first month of the marketplace. A single developer expanded his product surface by two orders of magnitude at zero marginal cost, by making one decision: *I ship the runtime, you ship everything else.*

There are two positions available here, and both beat building another agent:

| Position | Difficulty | Payoff | Timeline |
| --- | --- | --- | --- |
| Build the runtime itself | Hard | Platform economics, ecosystem gravity | 6+ months |
| Build plugins into a surging runtime | Low | Free distribution, fast feedback | 3 days – 2 weeks |

500 plugins sounds crowded. It was zero a month ago. **The ecosystem just opened and user growth is outrunning plugin growth** — that gap is the opportunity, and gaps like it usually stay open six to twelve months.

### 2. The harness layer is being rewritten, and the rewrite is open source

Prime Intellect open-sourced Prime Agent on August 5 with an explicit diagnosis: **current harness designs were built around the previous generation of models.** Fixed tool-calling schemas and context compaction force the model to work *around* its own scaffolding rather than leverage it. Static hand-engineered sub-agents, prompts, skills, and memory get set once at design time and never adapt to what the agent learns while running.

Two abstractions replace that:

**Recursive Language Model (RLM)** treats context as a variable and sub-agent delegation as function calls inside a REPL. The model’s *only* tool is a persistent IPython kernel; everything else is a pre-imported module inside it. Sub-agents fan out in parallel and return handles immediately:

|  |  |
| --- | --- |
| ``` 1 2 3 4 5 ``` | ``` auth = await rlm("Summarize the authentication flow in auth/. Reply when done.", name="auth-expert") api  = await rlm("Summarize the HTTP API layer in src/. Reply when done.", name="http-expert") # steer a child mid-flight await agent_message.send("Also cover middleware error handling.",                          receiver_role="child", receiver_name=api.name) ``` |

**Continual Harness** makes the harness’s own state — prompts, skills, memory, sub-agents — something the agent can CRUD from its own trajectory. Combined with agent-to-agent messaging, a session can orchestrate sub-agent swarms and talk to other Prime Agent sessions, deliberately scoped to parent/sibling/child so independent sessions cannot cross-talk.

The engineering details are where the real lessons are:

- **Session history is append-only JSONL.** Branching, forking, and cloning all happen inside one file by moving a leaf pointer. Full history always recoverable.
- **Sub-agents share the Running-Idle-Inactive state machine with root agents.** Idle for 30 minutes → unloaded from memory. Addressed by a user or agent → reloaded from disk. In deeply nested chats this saves enormous memory.
- **A spawned agent acts as garbage collector** for REPL state, running compaction and kernel cleanup asynchronously.

**What it means for you:** the harness is no longer “wrap a loop around a model.” It is a layer with real engineering problems — session recovery, memory lifecycle, cross-agent messaging, programmatic context access. And the best available implementation is readable source. **If you are building anything with multi-agent orchestration, reading Prime Agent and Herdr first will save you two months.**

### 3. Model selection is now a tiering problem, not a ranking problem

Qwen3.8 Max topped the Artificial Analysis Agentic Index this week. The ranking is not the story. The cost-per-task table the community immediately pulled out is:

| Model | Cost per task | Intelligence Index |
| --- | --- | --- |
| GPT 5.6 Luna max | $0.05 | 52 |
| Grok 4.5 high | $0.36 | 56 |
| GPT 5.6 Sol xhigh | $0.81 | 59 |
| Qwen3.8 Max | $1.13 | 58 |
| Opus 5 xhigh | $1.80 | 63 |

**36x price spread. 11 points of intelligence.** And the “best model” headline does not survive contact with the detail: Qwen3.8 Max leads the Agentic Index but was not run on DeepSWE or SWE-Atlas-QnA at all, and scores 81% on Terminal-Bench v2.1 against Sol’s 90%. **“Best model” stopped being a meaningful phrase in 2026. There is only “good enough at what price for this task.”**

The lever most people are ignoring sits in the same pricing table: Qwen3.8 Max charges **$2.00 input, $6.00 output, and $0.25 on cache hits — an 88% discount.** If your product has agents repeatedly reading the same codebase, the same document set, the same system prompt, getting prompt caching right changes your cost structure by an order of magnitude, not a percentage.

### 4. Taste is the last thing that has not been commoditized

The other high-heat HN piece this week (426 points) argues that when making things was expensive, **the expense did the filtering for us.** Nobody shipped a thousand mediocre variations, because a thousand variations cost a thousand times as much. The economics enforced a quality floor.

That floor is gone. The sharpest line: **“The friction was not an obstacle to developing taste. The friction was the curriculum.”** Judgment gets built the slow, humiliating way — you make something bad, you are forced to live with it, it fails in front of you. Developers who can generate fluently from day one will never be forced to sit in their own bad version, so they never take the course.

**But the most instructive part of that story is not the essay. It is what happened to it.**

After hitting the HN front page, the author was widely accused of publishing AI slop. He appended a post-mortem: not written by an LLM, not storyboarded, reviewed, or checked by one. He concedes people do not speak that way, but it is how he writes — **and an LLM writes that way too, because it trained on the same essays he grew up reading.**

For any indie developer doing content marketing, this is a new and immediate cost: **“reads like AI” is now a real trust penalty, and it is completely decoupled from whether you actually used AI.** Over-polished parallelism, short punchy sentences, the reversal-and-landing structure — that used to be style. It is now suspicion.

## Build Directions

Four directions where the window is genuinely open. Each with what to build, the stack, and rough cost and timeline.

### Direction 1 — Plugins for a surging agent runtime (best effort-to-reward ratio this issue)

**What to build:** not the runtime. Plugins into one that is already climbing. The validated demand shapes are already visible in what the community built unprompted: cross-device control clients, agent status visualization and alerting, **cost tracking (which agent burned how much)**, and shared session archives for teams. The author stated his own next problem publicly — *“a laptop, a VPS for the six hour job, a sandbox for risky code… those machines are disconnected.”* **That sentence is a roadmap, and what he has not built yet is your opening.**

**Stack:**

| Layer | Tool | Why |
| --- | --- | --- |
| Study | Herdr source (Apache-2.0) + Prime Agent | Learn the plugin surface before writing anything |
| Build | Claude Code or Cursor | Integration work against a known API is peak AI-coding territory |
| Distribution | The plugin marketplace itself | No landing page, no ads, no cold outreach |
| Monetization | Gumroad / Polar / Stripe | Free plugin as funnel, $9–29 pro tier or one-time |

**Why now:** 500 plugins in month one reads as crowded until you remember it was zero in month zero. The ecosystem just opened, and **the platform is doing your growth for you** — a condition that typically lasts six to twelve months.

**Cost & timeline:** zero infrastructure. A useful plugin ships in **3 days to 2 weeks.** This is the only direction in this issue you can start tonight and launch this weekend.

### Direction 2 — Tiered model cost routing (the 36x spread is the arbitrage)

**What to build:** a routing layer that picks the model tier by task difficulty — cheap tier for classification and extraction, mid tier for tool-calling work, top tier only for genuinely hard reasoning. **Do not sell “saves money,” which is too generic. Sell the audit:** which task classes cost what, and what quality you actually lose one tier down. Layer automated prompt caching on top for the 88% cache discount.

**Stack:**

| Layer | Tool | Note |
| --- | --- | --- |
| Routing | LiteLLM or a thin custom proxy | Resist heavy frameworks at the start |
| Difficulty classification | Cheapest available model | Classification cost is rounding error |
| Caching | Native provider prompt caching | Biggest single win — **build this first** |
| Quality floor | Auto-escalate and retry on low-tier failure | This is what makes it trustworthy |
| Hosting | Cloudflare Workers or a small VPS | $5–20/month |
| Dashboard | Next.js + Postgres/D1 | Standard |

**Why now:** the 36x spread is quantified and real, and most teams still route everything to one model. **But the moat is not the routing algorithm — anyone can write that. The moat is your accumulated data on which task types survive which downgrade.** Start early, the dataset compounds.

**Cost & timeline:** MVP in **2–4 weeks.** Price as a share of savings, or $29–99/month.

### Direction 3 — Wrap what you already know as a pay-per-call agent tool

**What to build:** this appeared last issue and a fresh instance landed this week, which is what makes it a pattern rather than an anecdote. AgisHub shipped 30 tools with a dual-channel structure: **free over MCP, paid over HTTP via x402 (USDC on Base).** The agent pays a few cents per call from its own wallet. Integration is one line — `claude mcp add agishub -- npx -y @agishub/mcp` — and it works across Claude, Cursor, Windsurf, and Claude Code.

**Stack:** MCP SDK (TypeScript or Python) → Cloudflare Workers → x402 middleware for USDC settlement, plus Stripe if you want fiat. **Pricing reference: $0.001–$0.12 per call.**

**Why now:** the value is not the unit price. It is that this path **bypasses the two things that hurt solo developers most — distribution and payment collection.** No signup flow, no subscription decision, no card form. The agent finds you, calls you, pays you, with no human in the loop. **The free-MCP-funnel / paid-HTTP-conversion split is the specific structure worth copying.**

**Cost & timeline:** if the capability already exists, wrapping it is **a weekend.** Cheapest experiment on this list.

### Direction 4 — Local-first single-binary tools (quiet, high retention)

**What to build:** the local-first Show HN stream continued all week — a local LLM benchmarking tool that cross-references HuggingFace trending models against your device specs, an on-device multi-agent system for Android, an account-free ad-free local recipe app, file-based Python HTTP endpoints with isolated per-file dependencies. **The shared shape: one binary, one local file, no network dependency.**

**Stack:**

| Layer | Choice | Why |
| --- | --- | --- |
| Language | Go or Rust | Single-file binary, trivial install |
| Storage | SQLite | **Resist the vector DB reflex** — higher cost, heavier deploy, questionable gain on code corpora |
| Search | BM25 / FTS5 | Lexical search is usually enough |
| Interface | MCP + CLI both | Callable by Claude Code / Cursor natively |
| Infra cost | Zero | No servers, no DB ops, no compliance surface |

**Why now:** this connects directly to the taste thesis. **Differentiation has moved out of the model layer and into the workflow layer.** Workflow pain is intensely personal and specific — exactly the terrain large platforms ignore and a single developer can own completely. Local tools also carry **noticeably higher one-time-purchase acceptance** than cloud services.

**Cost & timeline:** v1 in **2–6 weeks.** Open-core with paid sync/team tier, or a flat license at $29–79.

## Risk Factors

- **Plugin ecosystems live at the platform’s mercy.** Build on someone else’s runtime and one API change — or one decision to absorb your feature into core — zeroes you out. **Treat plugins as an acquisition channel, not the whole product. Keep the user relationship and the data on your side.**
- **Cost-saving products are structurally hard to sell.** Customers barely feel the money saved and feel a quality regression immediately. **One bad downgrade incident loses the account. The escalate-and-retry fallback matters ten times more than the routing logic.**
- **x402 is still a narrow rail.** It works, but it requires the caller to hold a USDC wallet. **Do not make it your only payment path** or you will fence out most potential customers. Keep a conventional card option.
- **“Writes like AI” is now a measurable reputation cost.** The taste essay was human-written and still got collectively judged as slop, forcing a public post-mortem. **For indie content marketing: over-polished prose now carries suspicion by default. Specific, noisy, concretely-detailed writing reads as more credible than clean writing.**
- **Single points of failure are the quiet killer for a one-person company.** GitHub Actions and Pages both degraded this week (332 comments). If your build, deploy, and docs site all sit on one provider, that day you are simply stopped. **At minimum, make deployment manually recoverable.**

## Action Recommendations

### If you are early (no stable product yet)

- ✅ **Go browse the Herdr plugin marketplace tonight.** Find the category that is obviously missing or obviously badly served. Lowest-cost, fastest-feedback move available this week.
- ✅ **Pick Direction 1 over Direction 2.** Plugins come with distribution attached; a routing layer means finding customers yourself. Get users first, get technical depth second.
- ✅ **Read the Prime Agent source even if you are not building multi-agent products.** Its handling of session persistence, memory lifecycle, and sub-agent messaging is the best publicly readable reference right now.
- ✅ **Tier your own project’s model calls today.** Pull out everything defaulting to the top tier and test one tier down. This is an hour of work and may cut your bill in half.

### If you already have product and users

- ✅ **Do prompt caching before you touch model selection.** An 88% cache discount is the largest single cost lever available, it does not affect quality, and it requires no re-testing.
- ✅ **Add an MCP interface to what you already have.** Near-zero marginal cost, effectively a free distribution channel, and agent-ecosystem call volume is still climbing.
- ✅ **Consider open-sourcing the core and charging for the service.** Herdr switched from AGPL to Apache-2.0 specifically so everyone could use it without friction. He optimized for spread, not defense. YC came to him after 25k stars.
- ✅ **Audit every single point of failure.** Build, deploy, domain, payments, docs — list them, mark which ones fully stop you, and prepare a manual fallback for the critical one or two.

## What It Means

The pattern across everything this week is that **the money is not where the attention is.**

Attention is on agents. The person who got 25,000 stars and a YC slot built the runtime underneath them and let 500 strangers build the surface on top. Attention is on which model won the benchmark. The actionable fact is that the winner costs 36x the cheap tier for eleven points, and an 88% cache discount is sitting in the same price sheet unused. Attention is on generating faster. The essay that took the front page argued the generation race was never worth winning, and then its author got accused of being a machine for winning it too cleanly.

Build cost has gone to zero, so everyone ships. What separates outcomes now is **positioning below or beside the crowded layer, knowing which tier is good enough, and being specific enough that nobody mistakes you for a machine.**

The cheapest move on this list takes three days. Start there.
