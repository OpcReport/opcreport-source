# Five Rivals Just Standardized Agent Plugins While Claude Code Removed the Human From Approvals

**August 10, 2026**

---

## Key Insights

Three things happened in five days. Individually they read like routine releases. Together they change what a solo builder actually ships.

**The plugin format war ended.** On August 6, OpenAI, Microsoft, AWS, Cursor and Vercel jointly shipped **Agent Plugins 1.0** — an open standard that packs Agent Skills and MCP server configs into one portable directory. Write it once and it loads in ChatGPT, Codex, GitHub Copilot, VS Code, Cursor and AWS Kiro. Until now every coding agent had its own format, so plugin authors maintained six parallel versions of the same thing.

**The human got removed from the execution loop.** Claude Code is flipping its permission model on August 14 for Pro, Max and Team users: auto mode becomes the default. No approval popup at every step. The agent runs unless an action is flagged irreversible, destructive, or reaching outside your environment.

**Guardrails became a paid product.** Docker shipped disposable isolated sandboxes for agents the same week, with cross-organization sandbox policy enforcement sold as a separate subscription.

Read them together and the shape is obvious: **what you can build is no longer the moat. Whether you can be installed — and whether anyone can reconstruct what happened after you were — is.** Distribution standardized and supervision disappeared in the same seven days. The gap between those two facts is the clearest commercial opening of the quarter.

**Signals that should change what you do this week:**

- **One format, six shipping clients.** Vercel wrote the initial proposal; a technical steering committee from AWS, Cursor, Microsoft, OpenAI and Vercel maintains it, with GitHub contributing, and it evolves in public on GitHub. It is still a **working draft, with no plugin store and no security spec** — both of which are simultaneously the risk and the window.
- **Human approval catches 13.6% of dangerous commands.** Anthropic ran a controlled study with 1,053 paid testers. Humans reviewing permission prompts caught **13.6%**. Auto mode’s separate AI classifier, which reviews every shell command, caught **89%**. In real usage people approve **97%** of prompts anyway. Auto mode teams shipped about **25% more pull requests**.
- **The category leader just published the ceiling for vertical agents.** Harvey — the $5B legal AI company — open-sourced LAB: **1,671 real legal tasks, 24 practice areas, 75,000+ expert grading criteria**, scored all-pass. At launch Claude Opus 4.7 led with **7.1%**; GPT-5.5 managed 2.1%. Three months later the top model barely clears **20%**.
- **The fine-tuning hardware floor collapsed.** Soup CLI streams one decoder layer at a time from CPU RAM, so peak VRAM is set by a single layer instead of the model. **Llama-3.1-8B trains on a 4GB RTX 3050 laptop at 119.6 tok/s in 3.32GB peak — bit-exact against a normal resident run.** Solo developer, Show HN and Product Hunt front pages the same week.
- **The small-team ceiling, and the warning attached to it.** OpenAI acquired NextSlide, an AI presentation startup barely a year old. Gamma, in the same category, reached **~50M users and $50M+ ARR with roughly 35 people**. Both facts matter: that’s the reachable altitude, and that’s who shows up when you reach it.

## Market Trends

### 1. Distribution collapsed into six clients; “can it be installed” replaced “can it be built”

For two years, anyone building agent tooling paid a hidden tax: one plugin format per host, one skill description per host, one MCP config per host. Ship one capability, maintain six copies. Agent Plugins 1.0 deletes that in a single move — a plugin is just a directory, a manifest plus your skills and MCP config, and six clients read it.

This matters more to solo builders than to platforms, because the tax it removes is exactly the kind small teams can least afford. **It also changes the minimum viable unit of a product.** Previously you shipped an app and owned the UI, auth, billing and retention problem. Now you can ship a plugin that lives inside the agent your user already has open, borrow their interface and their distribution, and own only the capability nobody else does well.

- **The most valuable property right now is that there is no store yet.** No ranking, no revenue share, no review system — and no incumbents. Whoever occupies the name and the docs for a specific capability inherits position when the store arrives. Windows like this usually last months.
- **The missing name is also information.** Anthropic isn’t on the list. Anthropic created MCP and shipped the skills-plus-plugins model everyone else is now standardizing without it. This is round two of the agent standards war, and this time the rest of the industry moved first.
- **Practical stance: don’t bet all distribution on a draft.** Implement the capability as an MCP server, wrap it in an Agent Plugins directory, and keep native install paths for each host. The extra wrapper is cheap; backing the wrong standard is not.

### 2. Human approval was falsified, and “isolation plus forensics” became a business

Anthropic’s data is more interesting than its product decision. **1,053 paid testers: humans caught 13.6% of dangerous commands, the classifier caught 89%, and 97% of prompts get approved in practice.** In other words, human-in-the-loop was mostly ceremony. Developers were trained by popup fatigue into click-through machines, and a model dedicated to reviewing shell commands outperforms them by a wide margin.

So the largest coding agent flipped its default from “human approves each step” to “human is out of the loop.” Not a settings tweak — an industry signal. **For the next year, assume the agents running on your customers’ machines are unsupervised.**

Docker’s move maps onto this precisely: disposable isolated sandboxes for agents (279 points, 161 comments on HN), with cross-organization policy enforcement broken out as a paid tier. Once manual approval disappears, the money moves to *constraining the environment* and *reconstructing what happened*.

- **Somebody sells the cage; nobody sells the flight recorder.** Docker solves “the blast radius stays inside the sandbox.” For a team under ten people, the sharper pain is that **after a run, nobody can say what actually changed**. Execution logs, file diffs, outbound calls, secret reads — that evidence chain has no small-team product.
- **11% is the new exposure.** The classifier catches 89%, which means roughly one in nine dangerous commands now executes with nobody watching. On your own machine that’s your problem. In a customer’s repo it’s a liability, and your terms of service almost certainly haven’t caught up.
- **The productivity gain is real, so the trend is not reversible.** ~25% more PRs from auto mode teams. When the payoff is that direct, complaints don’t move defaults — they create adjacent products.

### 3. The vertical agent ceiling got measured, and the answer is “nowhere close”

The weight of the Harvey story is in who published it: a $5B company selling legal AI open-sourced the public standard for whether AI can do a lawyer’s job. LAB contains **1,671 real legal tasks** across 24 practice areas plus transactional work — not multiple choice, but actual firm assignments like M&A data room review, each with agent instructions, client documents and expert-written rubrics totaling **75,000+ grading criteria**.

Scoring is all-pass: miss one criterion, fail the task. **Claude Opus 4.7 led at launch with 7.1%. GPT-5.5 managed 2.1%. Three months on, the leaderboard top barely clears 20%.**

That number should rewrite your positioning and your pricing:

| Positioning | What you’re promising | Deliverable today |
| --- | --- | --- |
| “Replaces the professional” | End-to-end autonomy in a liability domain | No — publicly falsifiable at ~20% all-pass |
| “Draft + rubric-driven QC + human signs” | Throughput and consistency | Yes — and it bills against real hourly cost |

- **Whoever writes the exam grades the market.** The category leader publishing the evaluation standard captures the definition of “good enough.” Every vertical with codified deliverables still has that seat empty.
- **LAB ships an execution harness plus multi-model adapters — copy the structure, not the domain.** Real tasks, expert rubrics, swappable model runner. That artifact is simultaneously your marketing asset and your product’s QC core.
- **Use it in reverse.** Legal teams are already using LAB to fact-check vendor claims. If you’re buying AI tooling, ask for all-pass rates on a public benchmark.

## Build Directions

### 1. One sharp pain, packaged as a portable Agent Plugin — before the store exists

**What to build:** pick a narrow, annoying, real workflow — Stripe revenue reconciliation, Shopify catalog QC, Terraform drift review, customs-document cross-checking for cross-border sellers — and ship it as an Agent Plugins 1.0 directory (manifest + skills + MCP config), verified installable across the six clients.

**Stack:** the public agent-plugins spec repo for format; TypeScript or Python MCP server for the capability (FastMCP-style framework is the fastest start); Docker Sandboxes for local execution testing; GitHub plus a docs site for distribution.

**Cost & timeline:** 1-3 weeks to a usable version, under $20/month infra.

**Pricing:** capability free, enterprise policy and private data connectors paid — or straight $9-29 per seat.

### 2. A flight recorder for unsupervised agents

**What to build:** once auto mode is the default, agents execute autonomously inside customer repos and no small-team forensics product exists. Build the audit layer: capture every shell command, file diff, outbound call and secret read; alert by category (file deletion, force push, writes outside the working directory, env var access); support step-by-step replay.

**Stack:** Claude Code / Codex hooks for event capture + OpenTelemetry for tracing + SQLite or ClickHouse for logs + a diff viewer. Reuse Docker Sandboxes for the execution boundary — don’t rebuild isolation, build evidence.

**Cost & timeline:** 3-5 weeks.

**Pricing:** $19-49 per developer per month, sold to sub-ten-person teams that want auto mode but can’t justify it to a client. That population is growing weekly.

### 3. Vertical assist priced against the 20% ceiling

**What to build:** choose a vertical with codified deliverables you can turn into a rubric — insurance claim adjudication, medical pre-authorization, municipal permitting, freight customs documentation. Don’t sell “we do it for you.” Sell **AI drafts + rubric-generated QC checklist + human signs**, priced per item rather than per seat.

**Stack:** frontier model for generation + your own rubric execution harness (copy the structure of Harvey’s open-sourced harness and multi-model adapters) + a review UI built for the professional. Recycle every human edit into your private eval set — that’s the only asset that compounds.

**Cost & timeline:** 4-8 weeks, and it requires a domain expert as co-founder or advisor, not a contractor.

**Pricing:** per case or per document. Buyers can compare directly against billable hours, which is the shortest path to a signed deal.

### 4. Stop tuning prompts, start tuning small models

**What to build:** pull the high-frequency, low-value, pattern-stable calls out of your frontier API bill — classification, extraction, formatting, first-pass screening. Mine 500-2,000 real examples from your own logs and fine-tune an 8B model to absorb them. Soup CLI reduced the hardware floor to hardware you already own: **Llama-3.1-8B on a 4GB RTX 3050 laptop, 3.32GB peak, 119.6 tok/s, bit-exact versus a resident run**, one YAML and one command, nine architectures supported, NVMe offload when RAM runs out.

**Stack:** soup-cli for training + Ollama or vLLM for serving + tiered routing in your gateway (routine turns to the local tuned model, judgment calls escalate to frontier).

**Cost & timeline:** a weekend plus hardware you already have.

**Productized version:** sell “fine-tuning on your own machine” to small teams with no ML headcount. YAML-driven means it drops straight into CI.

### 5. A supply-chain gate for plugins

**What to build:** the spec explicitly ships with **no security specification**, while plugin contents are executable skills plus auto-loading MCP servers — about to be installed into agents that no longer ask permission. That combination is a supply-chain hole that has already shipped. Build the pre-install gate: parse the plugin directory, scan the manifest, diff MCP tool schemas across versions, validate permissions against an allowlist, and expose it as a CI check.

**Stack:** static analysis + MCP tool schema diffing + a version-pinned private plugin registry. CLI for individuals, CI plugin for teams.

**Cost & timeline:** 2-4 weeks to MVP.

**Pricing:** free for individuals, $29-99/month for teams. This one races the store: once official review and a security spec land, the independent surface shrinks. Move fast, or weight the product toward private enterprise policy — the part platforms won’t build.

## Risk Factors

- **You are shipping executable code into a standard with no security spec, to hosts that just removed human approval.** The risk isn’t any one of “working draft,” “no security spec,” or “auto mode by default” — it’s the three of them landing in the same week.
- **Anthropic isn’t a launch client, so the standard may not be universal.** The largest coding agent entry point is absent from the founding list. Betting your entire distribution architecture on this draft is betting on an unfinished standards war. Keep native install paths alive.
- **Roughly one in nine dangerous commands now runs unreviewed.** If your product executes autonomously in customer repos, your liability surface expanded this month and your contract language probably didn’t. Fix docs and terms before chasing growth.
- **Promising autonomy in a liability domain invites refunds and litigation.** Top models barely clear 20% all-pass. Every “replaces your lawyer/accountant/doctor” claim is now publicly falsifiable with the vendor’s own benchmark.
- **Thin wrappers get eaten by the model vendors themselves.** OpenAI bought a one-year-old AI presentation company outright. The defense isn’t more features — it’s distribution position and proprietary data.
- **Platforms degrade, and single-platform dependence inherits their incentive drift.** A long post on a veteran bug bounty platform’s slide from community-driven to extractive pulled 265 points on HN this week. That’s the script every single-platform business eventually reads.

## Action Recommendations

**If you’re early:**

- ✅ Do one thing this week: wrap the workflow you know best as an Agent Plugins directory and verify it installs in at least three of the six clients. The window is “before the store,” not “after the standard matures.”
- ✅ Before you turn on auto mode, add execution isolation and post-run logging to your own setup. Whatever you plan to sell, run it on yourself first — that’s also your first prototype.
- ✅ Pull your highest-frequency call type out of the logs and fine-tune it into an 8B model this weekend. The hardware floor is now the laptop you own; skipping this is leaving money on the table.
- ✅ Don’t pick verticals that only work at full autonomy. Pick the ones where “draft plus human signature” already saves billable hours.

**If you have a product and revenue:**

- ✅ Repackage your existing capability as a portable plugin and run it as a second acquisition channel in parallel. Your app doesn’t come down; the plugin just puts you inside the window your users already have open.
- ✅ Ship execution forensics and permission boundaries now, before a customer incident. Auto mode lands August 14 and your customers will enable it before your documentation catches up.
- ✅ Write a rubric for your vertical and publish part of it. Whoever publishes the standard defines the market — worth more than another feature-release post.
- ✅ Implement tiered routing: classification, extraction, formatting and first-pass screening down to a locally tuned small model; only judgment escalates to frontier. Highest-ROI refactor available right now.
- ✅ If your product is a thin layer over a frontier vendor’s surface, answer this quarter: where is your distribution position, and what proprietary data do you hold? No answer means waiting to be acquired or routed around.

## What It Means

Two weeks ago the constraint on a one-person software business was cost. This week it’s position.

Distribution just standardized: one plugin directory, six clients, no store yet, no gatekeeper yet. At the same moment supervision was deleted by default, which means the software you ship will run in other people’s environments with nobody watching it — and the tooling to prove what it did doesn’t exist for teams your size. Meanwhile the category leader in the most lucrative vertical published data showing that full autonomy in a liability domain is roughly 20% deliverable, which quietly kills the “replaces the professional” pitch and validates the boring one that actually bills.

So the play isn’t a better agent. It’s **occupying the new distribution surface while it’s unguarded, and selling the accountability layer the standard forgot to specify.** Ship the plugin before the store exists. Build the flight recorder before the first incident. Price against the 20% ceiling instead of pretending it isn’t there.

Capability was the moat in 2024. Unit economics was the moat last month. Position is the moat now.
