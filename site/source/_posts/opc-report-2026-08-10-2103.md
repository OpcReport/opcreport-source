# Autonomous Execution Became the Default and Sandboxes Became Free — Nobody Is Selling the Lock

**On the same day agents got permission to run unattended, they got a box to run in. What nobody shipped is the thing that forces them to stay inside it.**

---

## Key Insights

The signal in the last 24 hours is not a model. It is a collision. Anthropic **turned auto mode on by default in Claude Code** (253 points, 261 comments). Docker shipped **Docker Sandboxes** — disposable, isolated environments for coding agents, installed with one brew or winget command, supporting Claude Code, Codex, Gemini CLI, Copilot CLI, OpenCode and Kiro (326 points, 191 comments).

One side released the brake. The other handed out a box. That looks complementary until you read the sharpest comment in the thread: **sandboxing limits what an agent can do, but it does not enforce that the agent must run inside the sandbox. You need a separate control layer for that boundary.** Docker made the box free. The lock is still unsold.

Running alongside that, a field report with 183 comments supplied the other half of the picture. An engineer genuinely trying to adopt agentic development signed up for ONA — the cloud agent service OpenAI acquired a couple of months ago — and watched it **burn nearly the entire $20 of credit thrashing on fetching a todo list from Linear so it could pick something to work on**. Zero work produced. Her conclusion is hard to argue with: if agentic development worked the way it is marketed, the companies selling it would be shipping the most polished software on the market. She could barely get past the login screen.

Stack those three and the read is clear. **The technical barrier to autonomous execution is gone. Everything left is engineering and economics** — how to enforce a boundary, how to stop the orchestration layer from burning the budget before any work starts, and how not to be liable when something goes wrong. None of those three has a decent product yet, and none of them requires you to train a model.

### Signals worth acting on

- **The sandbox layer just got absorbed and made free.** Docker Sandboxes installs in one command across macOS, Windows and Linux, targeting every major agent harness. **If “isolated sandbox for agents” was your product, this week it became a feature.**
- **The gap it leaves is unusually legible.** Community consensus: isolation is not enforcement. Nothing stops an agent from running on the host. People are hand-rolling network restriction layers; one commenter had Claude write their sandbox for them. **A wave of DIY substitutes means the product shape hasn’t been found yet.**
- **Orchestration waste is now quantifiable.** **$20 of credit consumed at the “fetch the task list” stage**, with zero output. That is not an outlier — it is the shared pathology of every multi-step agent product: startup overhead lands before value does.
- **The harness is not the moat; the workspace is.** YC’s own open-source `qm` (multiplayer agent harness) has taken **12,890 stars since July 29**. Its README is explicit that Pi, OpenCode, Codex and Claude Code all drive the same core, so a deployment is not tied to a vendor. What it actually sells is per-person isolated workspaces with scoped memory, files, keychain, permissions and crons.
- **Translating the web for machines is already earning ad revenue.** Time converted its pages to markdown and has **begun serving ads to AI agents** — formatted as FAQs, labeled sponsored, with first buyers live. Mobian’s data puts brands running their own markdown pages at **about 15%**. In parallel, `firecrawl/anydoc` (Word/PPT/Excel/PDF/EPUB → clean markdown, in Rust) hit **13,141 stars in 7 days**.

## Market Trends

### 1. Once autonomy is the default, liability moves from the vendor into your container

Anthropic’s reasoning for the default is pragmatic: without it you get prompted incessantly, and since plenty of people run auto mode anyway, you may as well make it the mainstream path and concentrate on making that path safe. The thread split hard on whether that is defensible. The interesting part is not the argument — it is **what people were already doing**.

A visible cohort has been running `--dangerously-skip-permissions` inside Docker or Podman containers for months, specifically so they can get up and walk around while the agent works. Others approve from mobile via remote control. In other words, **the human checkpoint the vendor removed had already been replaced by users with containers and remote approval.** Docker’s launch standardizes that folk practice into one install command.

That is a complete “pattern validated → platform absorbs it” cycle, and it took a few months.

- **Good news: isolation is no longer your problem.** If you are building an agent product, you can now depend on a mature runtime boundary and spend your engineering budget elsewhere.
- **Bad news: if the sandbox *was* the product, move one layer up or down this week.** Down is enforcement — guaranteeing egress only happens through the controlled path. Up is audit and attribution — what did the agent actually touch.
- **Someone is already building the comparison table for this category.** A public dataset of agent sandboxes appeared (pleasedonotescape.com, maintained as YAML on GitHub, every claim traced to a primary source). **When a category grows a comparison directory, it has entered commodity competition.** That is the fastest available crowding test — run it against your own direction.

### 2. Orchestration’s real cost: the money is gone before the work begins

The $20 story deserves to be read in full by anyone shipping agent products. The author wanted something concrete and reasonable: turn vague improvement requests into clear requirements, reconcile them with existing planned work, scope them into implementable features, then run design, testing, implementation, QA and deployment. That is precisely what these platforms advertise. What she got was a desktop client she could not log into, a web flow that took many clicks and redirects, and then a full credit balance spent **thrashing to retrieve todos so it could choose one**.

Her framing is the line to pin on the wall: **these companies are the best argument against their own sales pitch.** If it worked, the sellers would be the primary beneficiaries.

> **What this means for you: differentiation is not “my agent handles complex tasks.” It is “my agent spends almost nothing before it starts.”** Context retrieval, list traversal, retrying broken integrations, refreshing expired tokens — invisible in a demo, fully billed in production. Treat *cost-to-first-useful-action* as a headline metric. It is the most underpriced product difference available right now.

- **Integrations are the primary failure source, not a bonus feature.** The complaint was not that the model is dumb. It was more integrations to debug, more tokens to refresh, more bills to track. **Every integration you add is another path for money to leak.**
- **Do not use one model for thinking and fetching.** List retrieval, filtering, formatting should run on a small local model or plain code. The failure mode above is the most expensive resource doing the cheapest work.
- **The orchestration UI layer has near-zero retention.** In this week’s OpenChamber thread (164 points, MIT licensed), users casually listed substitutes — Paseo, conductor.build, superset.sh, Cursor Cloud Agents — and several described switching twice in a few weeks. You can grow fast at this layer. You cannot hold anyone unless you also hold their data or their permissions.

### 3. The web is growing a machine-readable twin, and it already sells ads

Time converted its pages into stripped-down, text-only markdown copies that drop design and images. The original motive was visibility in generative search. The new motive is revenue: they are **serving ads inside those markdown pages, aimed at AI agents**, formatted as FAQs carrying brand information and labeled as sponsored content. Their sales motion is the tell — they pitch first to **brands that have already converted their own corporate sites to markdown**, because those brands are already thinking about being read by machines. Roughly **15% of brands** currently run their own markdown pages.

The tooling layer is compounding at the same time. `anydoc` — Word, PowerPoint, Excel, OpenDocument, RTF, EPUB, CSV and PDF into clean markdown, written in Rust with Node and Python bindings — took **13,141 stars in a week**. Microsoft’s `skill-recorder` — record an on-screen work session, reconstruct it as intent plus ordered steps, emit a reusable Skill — took **2,777 stars in 12 days**.

A supply chain is forming: **translate human-formatted content and human-performed procedure into structures agents can consume.**

| Layer | What it translates | Live example | Status for a solo builder |
| --- | --- | --- | --- |
| Web pages | HTML → markdown twin | Time (ads live, FAQ format, labeled) | Open; ~15% brand penetration |
| Documents | Office/PDF/EPUB → markdown | anydoc (13.1k stars/7d) | Crowded at the generic layer; open per-vertical |
| Procedure | Screen recording → reusable Skill | skill-recorder (2.8k stars/12d) | Wide open; the bottleneck is domain access, not code |
| Workspace | Company context → scoped agent env | qm (12.9k stars/12d) | Open below team size ~10 |

- **If you own any content, this is a revenue experiment you can run now.** Do not wait for agent traffic. Ship the markdown twin so you are citable and monetizable. **15% penetration means early today, late next year.**
- **The translation opportunity is not just web pages.** Documents, spreadsheets, procedures, internal knowledge — anything formatted for human eyes needs a machine edition. Both projects above cleared a thousand stars in under two weeks because the demand is non-negotiable.
- **Skills can be captured from demonstration rather than authored.** Record an expert doing the real thing once, emit a reusable capability pack. **That makes “selling the process” engineering-feasible for the first time.**

## Build Directions

### 1. Build the lock: an enforcement layer for agent execution boundaries

**What to build.** Docker gave away the box; nothing guarantees the agent is in it. Ship enforcement: the agent process can only reach the network through a controlled egress, every tool call and request passes an auditable proxy, and each run emits a signed attestation that it executed inside isolation and touched exactly these resources. The buyer is unambiguous — **every small team that just had auto mode switched on by default and still has to answer to a client or a compliance reviewer.**

**Stack.** Go or Rust for the egress proxy (it must be light and must not fall over) + nftables/eBPF network policy on Linux, container networking on macOS + OpenTelemetry for the call chain + signed run attestations + compatibility with Docker Sandboxes and Podman rather than competition with them.

**Cost and timeline.** 4–6 weeks to a demoable version. **Pricing:** $19–49 per developer per month, or per seat. Note that Docker’s own developer tiers sit at **$9–24 per user per month** — that is the anchor in your buyer’s head. Be clearly cheaper, or clearly solve what Docker explicitly does not.

### 2. Orchestration waste audit: make cost-to-first-action an optimizable number

**What to build.** Aim directly at the $20 story. A transparent gateway that tags every call by phase — context fetch, retrieval, planning, actual execution, retry — computes **how much was spent before the first useful output**, and returns actionable cuts: which fetches should be cached, which calls should drop to a local model, which retries are integration misconfiguration rather than model failure.

**Stack.** An OpenAI-compatible proxy gateway as the interception point + phase tagging + SQLite or ClickHouse for detail + context snapshot caching + a local 30B-class model as the cheap replacement target + shadow traffic to prove accuracy does not regress.

**Cost and timeline.** 3–5 weeks. **Pricing:** $29–79/month, or package it as a one-off diagnostic (1–2 weeks per client, $2,000–6,000). **Why now:** the complaint has shifted from “the model isn’t smart enough” to “I don’t know where the bill went.” **The second one is solvable with software. The first is not.**

### 3. Markdown twins and agent ad slots for content sites

**What to build.** For small publishers, B2B sites and docs sites: one-click generation of a machine-readable twin — style-stripped markdown pages, structured FAQ blocks, llms.txt and citation metadata, with clearly labeled sponsor slots reserved. A major publisher has proven the path and is already collecting money, and **only ~15% of brands run their own markdown pages.**

**Stack.** anydoc or Firecrawl for conversion + build-time static markdown twin + Cloudflare Workers or any edge platform for delivery and bot detection + simple sponsor-slot templates with impression counts.

**Cost and timeline.** 2–4 weeks to self-serve. **Pricing:** $19–99/month per site, or revenue share on slots. **Risk:** measurement and verification standards for agent-facing ads do not exist yet. Do not build the whole revenue model on the share.

### 4. Package expert procedure as sellable Skills

**What to build.** Use the now open-source-validated pattern — record, reconstruct into intent plus ordered steps, emit a reusable pack — against a narrow vertical you actually understand: month-end reconciliation, ad scheduling, first-pass insurance claims triage, cross-border compliance filings, clinic rostering. **You are not selling software. You are selling packaged experience** — the one asset a platform cannot absorb with a single install command.

**Stack.** skill-recorder’s open implementation as the capture reference + expose capability as an MCP server + distribute packs via git repositories (qm already imports skill packs from git, which is how the de facto standard is forming) + replay validation against a local model.

**Cost and timeline.** 1–3 weeks per pack; the real cost is finding a practitioner willing to be recorded. **Pricing:** $200–800 one-off per pack, or subscription with updates. As a consulting deliverable, $3,000–10,000.

### 5. An agent workspace and permission layer for teams of 2–10

**What to build.** `qm` proves the point: **the valuable object is not the harness, it is a per-person isolated workspace with scoped memory, files, keychain, permissions, crons and shareable skills.** But it is designed for company scale. The gap is small teams: three people, one shared pile of API keys, everyone running auto mode, nobody able to say whose agent read what. Build the light version — scoping by person and project, keys that never enter agent context, skills shared by explicit grant, every cross-scope access logged.

**Stack.** Postgres for sessions and memory + one durable sandbox per scope (use Docker Sandboxes; do not build your own) + pluggable harness so Claude Code, Codex and OpenCode drive the same core + Slack or a chat surface as the entry point to keep adoption cheap.

**Cost and timeline.** 5–8 weeks — the heaviest direction here. **Pricing:** $10–25 per user per month. **Why it justifies the weight:** this layer holds data and permissions, and it is the only position in this report with real retention. **Orchestration UI users switch tools weekly. Workspace users do not.**

## Risk Factors

- **Isolation is not governance — do not sell a sandbox as a compliance answer.** An agent can simply start outside the box. Until you ship enforcement, “we’re secure” does not survive a serious question.
- **Autonomous execution now has legal edges.** Australia reported what is described as its first known autonomous AI-assistant cyber attack, against a gym website. **When auto mode is the default, what your agent does is what you did.** Complete action logs are self-defense, not a feature.
- **The MCP and plugin ecosystem is being actively targeted.** This week the Blender MCP maintainer’s GitHub account was compromised, and a widely used WordPress forms plugin shipped a backdoor. **Every third-party MCP server you wire in is an unaudited execution path.**
- **Assume your feature gets commoditized.** Sandboxing went from product to install command in months, and YC open-sourced a harness itself. **Anything you can describe in one sentence should be assumed free within a year.** Moats live in private data, domain experience and permission relationships.
- **Do not overestimate mainstream agent demand.** Consumer agent adoption remains a rounding error next to chat assistants. Selling tools to people already working with agents is far more tractable than educating a general market.

## Action Recommendations

**If you are early (no product, or just launched)**

- ✅ **Do one small thing this week: run your own agent workflow inside Docker Sandboxes** and log where it breaks. Your friction list is your product list.
- ✅ **Measure cost-to-first-useful-action** on whatever agent tooling you use today — tokens burned between instruction and first real output. The number will surprise you, and it is the easiest gap to attack.
- ✅ **Do not build another sandbox or another orchestration UI.** This week one got absorbed by a platform and the other filled with interchangeable substitutes. Move toward enforcement, audit, or vertical Skill packs — things that take a paragraph to explain and are hard to leave.
- ✅ **If you own content, ship the markdown twin this month.** Near-zero cost, and penetration is still ~15%.

**If you have a product and paying users**

- ✅ **Replace your homegrown sandbox with the standard one now**, and redirect that engineering time into enforcement and audit. Those are the next questions your customers will ask.
- ✅ **Expose cost breakdown in the product**: per run, per phase, including how much went to retrieval and retries. While competitors hide the bill, transparency itself is a feature.
- ✅ **Keep the harness pluggable.** The YC reference implementation explicitly drives multiple harnesses from one core; that is now the default expectation. **Any hard-coded single vendor is a scheduled outage.**
- ✅ **Audit the third-party MCP servers and plugins you depend on** — pin versions, verify maintainers, restrict their egress. This week’s two supply-chain incidents will not be the last two.
- ✅ **Turn your customers’ procedures into Skill packs and sell them back.** It is the shortest path from one-off delivery to recurring revenue, and the hardest asset to copy.

## What It Means

The capability argument is over. Agents will run unattended, and the tooling to contain them is free as of this week. What remains unsolved is unglamorous and entirely buildable by one person: proving the boundary held, showing where the money went before any work happened, and translating human formats and human procedures into things machines can consume. Those three are where the next twelve months of durable solo revenue lives — not because they are exciting, but because the people selling autonomy have conspicuously declined to build them.
