## Market Trends

### 1. AI coding entered the “writes-its-own-code” phase

The 2026 fight is not “which autocomplete is more accurate” — it’s “which agent finishes the job.” Claude Code (Anthropic) runs as a terminal-native agent: 72.5% on SWE-bench, 1M-token context, native MCP, and it will modify files, run your commands, and commit. Codex (OpenAI) ships as a CLI with “minimum intervention, maximum safety” — three approval tiers plus an OS-level sandbox, and the client code is fully open source and auditable. Both are now the most active AI-coding entry points on GitHub; directories like Codegen surface them as “search the tool, then let the agent work.”

- For solo founders: the friction from idea to a shippable PR is now days, not weeks. What’s scarce is defining the problem and accepting the result — not typing.
- On选型 (tool pick): reach for Codex when audit/compliance matters, Claude Code for deep refactors and long context.

### 2. Coding directories + a “skill market” appeared; discoverability is the new battlefield

Codegen (codegen.com) launched as an AI-coding tools and skills directory — Claude Code, Cursor, Windsurf, plus agents and skills become searchable (`codegen search "summarize a PR"` returns a ready-made skill; `claude skill add` installs it). Reusable agent workflows now circulate like npm packages. YC-track repos are showing up too: an “AI co-founder skill” for Claude Code / Codex / terminal agents that hands you YC-style advice on idea validation, PMF, user interviews, and runway — a thinking partner, not an FAQ bot.

- Signal: the distribution of agent capability is shifting from model-vendor trench warfare to “who lets others reuse my workflow fast.”
- Opening: package the skill / agent template you’ve already hardened for one vertical into a shareable or sellable asset.

### 3. The agent orchestration stack split into four routes

Frameworks layered out clearly in 2026: **LangGraph** (state-graph runtime, supports loops and self-correction, best for deterministic long flows), **OpenAI Agents SDK** (managed SDK, fastest onboarding), **CrewAI** (multi-role collaboration), and **Dify** (visual workflow builder a non-technical co-founder can assemble). GitHub also surfaced lightweight open pieces: Helicone (open-source LLM observability, one-line integration for monitoring/evals/experiments, YC W23), the llm-gateway topic (794+ repos, Rust core, one SDK for 100+ models), and a local, privacy-first desktop agent that records your screen 24/7 and plugs into your own agents. Selection now collapses to six axes: state management, deterministic control, human approval, observability, multi-agent support, protocol integration.

- For solo founders: get the MVP running on Dify / OpenAI Agents SDK before hand-rolling orchestration.

## Risk Factors

- **Commoditization:** generic chatbots and generic agent templates are already oversupplied; a “wrapper” with no scenario moat won’t survive three months.
- **Self-loop burn:** multi-agent reflection/retry loops without a cost gate explode the bill exponentially — observability and limits come first.
- **Deployment gap:** agents look smart in demos and fall over on edge cases in production (the community already saw an AI PR rejected for convoluted logic); acceptance matters more than generation.
- **Compliance / lock-in:** binding your core flow to one model or one plugin ecosystem means a price or policy change can shut your product down overnight.
