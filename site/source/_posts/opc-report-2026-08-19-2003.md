# Your Agent Needs Its Own Computer: Per-Minute Compute Is the New Line Item

> **TL;DR:** The harness layer just collapsed to free — Vercel Labs shipped `fx`, a 6.39 MB Apache-2.0 coding agent with a 10 µs cold start. Meanwhile the *machine* your agent lives on became a metered product: persistent agent VMs from **$0.013/hr** CPU and **$0.836/hr** GPU, billed by the minute, suspendable. If a coding agent runs 6–8 hours on one feature, your unit of sale is a task, not a seat. Build the control plane, not another CLI.

---

## Key Insights

The interesting shift this week isn’t a model release. It’s that **“where does the agent run” became a real cost center and a real product gap at the same time.**

Two things happened in parallel. First, the harness — the shell that runs a coding agent’s tool loop — got commoditized to nearly zero. Second, long-horizon agent work outgrew the laptop, so persistent per-minute machines became a category with YC money behind it.

For a one-person company, that combination is unusually actionable: your P&L gets a new line item you didn’t have last quarter, and the control layer above that line item is almost entirely unbuilt.

**Decision-relevant numbers:**

- **$0.013/hr** — entry price for a persistent CPU agent VM (machine0, YC-backed). Roughly **$9.40/month** if left on; suspend and billing stops, snapshot and resume later.
- **$0.836/hr** — entry GPU price on the same platform, scaling to 8×H200. Per-minute GPU without an annual contract is now a solo-accessible input.
- **6.39 MB / 10 µs** — binary size and cold start of `fx`, Vercel Labs’ open coding agent. Single-digit MB memory baseline, so you can pack many isolated instances per box.
- **6–8 hours** — how long a coding agent runs on one complex feature, per machine0’s founder. This is why “per seat” pricing is the wrong shape for agent work.

## Market Trends

### 1. The harness layer went free; cost moved to the runtime

For the last two quarters everyone was building the shell: the CLI, the tool-call loop, context management. That layer is now being flattened by open source from platform vendors.

`fx` hit Hacker News on August 18 and states the position bluntly — “tiny, open, native coding agent.” Written in Zig, 6.39 MB binary, 10 µs cold start, Apache-2.0, model-agnostic, WASM builds available, and explicitly designed for **embedding in larger systems and agent sandboxes**. Its stated design goal is to feel like a Unix shell rather than an “IDE in the terminal.” In the same window, `yc-software/qm` appeared on GitHub described as a “multiplayer agent harness for work,” and DeepSeek’s open harness (covered earlier this week) points the same direction.

What follows from this:

- **A general-purpose harness is not a business.** Open, free, and small enough to embed means zero moat.
- **Free harness pushes value to both ends** — the vertical workflow above it, and the execution environment below it. Those are the two places money still changes hands.
- **Binary size stopped being a nerd metric.** 6 MB plus single-digit MB RAM is the precondition for “one dedicated agent per customer” as a viable unit economic model on a single large box.

### 2. Long-running agents created a new primitive: the metered, agent-owned machine

machine0’s Show HN framed the problem list precisely, and every one of these is a wall solo builders actually hit:

- **Resources:** a few agents on a large codebase saturate local RAM and CPU; training and RL need GPUs you don’t own.
- **Security:** running `--yolo` on your personal machine is one prompt injection away from exfiltrated credentials.
- **Availability:** close the laptop, the agent dies mid-task.
- **Isolation:** there’s no clean boundary between your stuff and the minimum your agent actually needs.

The answer being sold is a computer per agent: 1–60 vCPU, up to 240 GB RAM, optional H100 / H200 / L40S / MI300X / RTX Ada. Every VM gets a public static IP and an HTTPS endpoint at `<vm>.mac0.io` — no NAT, no tunnels. Start, suspend, snapshot, resume; suspension stops billing. Images are NixOS (deterministic builds, one-command rollback) or Ubuntu preloaded with Docker, Node, Python, Claude Code, and Codex. Every operation is a CLI command with `--json`, plus a remote MCP server so agents drive provisioning themselves. Five regions, 99.99% VM-level uptime claimed, images open sourced.

**Why this changes your architecture, not just your bill:** once an agent can open a machine, install its environment, finish, and suspend itself over MCP, your product stops being “always-on server plus queue” and becomes “spin up disposable machine on demand, destroy after.” Same work — one burns money monthly, the other burns money only during the minutes of actual work.

### 3. Model cadence can deliberately brake — don’t stake your roadmap on the next jump

On August 18, OpenAI published something counterintuitive: it **slowed its own scaling pace on purpose.** The stated triggers were a model-evaluation security incident plus preliminary evidence that an upcoming model, Astra, may meet the Critical cybersecurity capability threshold under its Preparedness Framework. Concrete actions: a **two-week pause** on RL training for the latest deployment-bound models while research environments were hardened and red-teamed and monitoring coverage expanded — and the **largest planned frontier RL run remains on hold** pending smaller-scale evaluations and alignment evidence.

A structural signal landed the same week: Modular — acquired by Qualcomm for $3.9B in stock, closed July 29 — used ModCon to open-source Mojo and push it to 1.0, while also publishing an official **Agentic Skills** repository. Vendors are now shipping reusable agent skills as a first-class artifact.

Three implications for a one-person company:

1. Any plan shaped like “this feature works once the next model ships” needs slack. Capability delivery is now gated by safety process, and that gate really closes.
2. **Containment is becoming a product surface.** If frontier labs are hardening research environments against injection and credential leakage, your customers face the same class of risk with none of the staffing.
3. Official skill registries mean **reusable workflows are a distribution vehicle.** You can be a supplier inside someone else’s catalog instead of buying traffic from zero.

> ⚠️ **Runtime risk note:** a widely-read HN post this week questioned Bun 1.4’s Rust rewrite. Core runtimes are in flux, and last week’s multi-hour global code-hosting outage is still fresh. “Boring reproducibility” is now a paid feature — which is exactly why agent platforms are defaulting to NixOS.

## Build Directions

### 1. Agent ops console (provision / snapshot / kill runaway agents)

- **What to build:** a control plane for indie devs and small teams — spin up an isolated machine per task, auto-suspend on completion, auto-kill on timeout or budget breach. One timeline per agent showing which box it opened, how long it ran, what it cost.
- **Stack:** machine0 CLI/MCP (or Fly Machines, E2B, and similar per-second sandboxes) underneath + `fx` as the embedded harness + Next.js console + Supabase for run records and budget rules + Inngest or Trigger.dev for timeouts and cleanup.
- **Cost / timeline:** $10–40/month of your own compute with sane suspend policy; 2–3 weeks to a chargeable version.
- **Why now:** the capability just shipped and the control surface is empty. Vendors give you CLI and MCP; nobody gives you budget guardrails.

### 2. Credential broker and injection containment for agents

- **What to build:** stop letting agents hold long-lived keys. An MCP proxy layer: agent requests an action → proxy mints a short-lived least-privilege credential → full audit trail → human confirmation for destructive operations. Sell to agencies and contract teams currently running `--yolo`.
- **Stack:** self-hosted harness (`fx` or DeepSeek Harness) on an isolated VM + short-lived tokens (Infisical, Doppler, or cloud STS) + your own MCP proxy for egress allowlisting and redaction + Postgres for the audit stream.
- **Cost / timeline:** zero license cost, $10–30/month compute; 3–4 weeks to a demoable loop.
- **Why now:** frontier labs publicly hardening containment is the strongest category endorsement you’ll get, and small customers have no equivalent capability. They pay monthly for “nothing bad happened.”

### 3. Overnight agent jobs — sell the task, not the seat

- **What to build:** pick **one** unglamorous 6–8 hour job and make it orderable: backfilling tests on a legacy repo, major framework migrations, bulk doc restructuring, dirty-data dedupe. Customer submits repo or dataset → you spin a machine overnight → they get a PR or report by morning.
- **Stack:** persistent VM + Claude Code / Codex CLI headless + job queue (Inngest / Trigger.dev) + Stripe usage billing + a diff report page.
- **Cost / timeline:** most single runs land in the single-digit to low-double-digit dollar range of compute; price at 5–10×. First orderable category live in 1–2 weeks.
- **Why now:** the infrastructure for long horizons just landed and nobody has packaged it as an order form yet. Task pricing also sidesteps the token-cost blowups covered earlier this week.

### 4. Vertical skill packs as a distribution wedge

- **What to build:** encode the one workflow you know best (Stripe billing migrations, compliance doc pipelines, industry-specific data validation) as a reusable skill pack. Publish into official and third-party registries, use the free pack for lead flow, convert complex cases into services or a private-tier subscription.
- **Stack:** Claude Code / Codex skill format + one verifiable example repo + a minimal landing page (Astro or Next) + form-to-consult.
- **Cost / timeline:** near zero, one weekend. Conversion comes from registry placement, not ad spend.
- **Why now:** vendors are maintaining official skill repositories, which makes the registry an app-store-shaped entry point while supply is still thin.

### 5. Reproducible stack templates and rollback runbooks

- **What to build:** sell “boring and it doesn’t break” to indie devs: a NixOS flake or pinned Docker composition + one-command rollback + mirrored remote + backup CI + incident runbook. Positioned as insurance against runtime churn and platform outages.
- **Stack:** NixOS flakes or Ansible + dual-write GitHub Actions and a backup CI + your own health checks + template repo subscription.
- **Cost / timeline:** first template in a weekend; $9–49/month subscription or a one-time $99 pack.
- **Why now:** core runtimes are being rewritten and a global code-hosting outage happened last week. A one-person company has no colleague to absorb downtime.

## Risk Factors

- **Silent compute drift.** The danger of per-minute billing isn’t the rate, it’s forgetting to suspend. Without budget alerts, a $20 toy becomes a $200 invoice you didn’t watch happen.
- **Injection equals breach.** Give an agent a real machine and production keys, and prompt injection is wired straight into your revenue. Isolation has to be architectural, not disciplinary.
- **Harness commoditization.** A 6 MB, open, model-agnostic shell already exists. Anything whose core pitch is “a nicer agent CLI” gets flattened within two release cycles.
- **Cadence uncertainty.** Frontier training can genuinely be held — the largest planned RL run is on hold right now. Roadmaps that assume “next quarter’s model fixes this” are bets, not plans.
- **Platform absorption.** Infrastructure vendors are now shipping official skills and registries. Pure wrappers get built in. Own domain knowledge or own the customer relationship.

## Action Recommendations

**Just starting (no paying customers yet)**

- ✅ Run a compute audit this week: take your longest recent agent task, run it once on per-minute infrastructure, record actual minutes and dollars. That number is your pricing floor.
- ✅ Stop running `--yolo` on a machine that holds production keys. Move to an isolated VM; hand the agent short-lived least-privilege tokens only.
- ✅ Pick one 6–8 hour dirty job from Direction 3 and make it orderable within a week. Validate willingness to pay with task pricing.
- ✅ Package your best-known workflow as a skill pack and publish it. Take registry leads before you build a funnel.

**Already earning (hardening or expanding)**

- ✅ Add hard budget ceilings and timeout-destroy per customer and per task. Turn compute from an unpredictable cost into a quotable one.
- ✅ Treat the harness as a swappable part — keep a migration path to an open, small-footprint shell — and push differentiation into domain workflow and validation.
- ✅ Put isolation and audit into your sales material. Buyers now ask which permissions the agent held and what logs exist.
- ✅ Pin your runtime with Nix or containers and rehearse a rollback once. Don’t discover you have no fallback during the next core-runtime rewrite or hosting outage.

## What It Means

The build cost of software already collapsed. This week the collapse moved one layer down: the shell that runs your agent is free, and the machine that hosts it is metered by the minute. That reshapes the solo business in two concrete ways. Your pricing unit should follow the work — tasks and runs, not seats. And your defensible product is no longer the agent; it’s the **control plane around the agent**: budgets, isolation, audit, reproducibility, and the domain knowledge that decides what the agent should attempt in the first place. Vendors will keep giving away the shell. They will not do your metering, and they will not take your customer’s risk.
